# OMS Pro — نسخهٔ بازنویسی‌شده

مدیریت سفارش، حساب مالی، تسویهٔ تأمین‌کنندگان، سهم همکاری و فروش اسنپ‌پی —
بازنویسی‌شده با Vite + React + TypeScript + IndexedDB (Dexie)، به‌صورت PWA
نصب‌شدنی، برای اجرا روی GitHub Pages.

وضعیت کامل پروژه (چه چیزی ساخته شده، چه چیزی نه) در `oms-pro-analysis-report.md` است.

## پیش‌نیاز

Node.js نسخهٔ ۲۰ یا بالاتر.

## اجرای محلی (dev)

```bash
npm install
npm run dev
```

آدرسی که در ترمینال چاپ می‌شود (معمولاً `http://localhost:5173`) را باز کنید.

## اجرای تست‌ها

```bash
npm test                # اجرای همهٔ تست‌های خودکار (اکنون ۵۳ تست)
npm run typecheck        # بررسی نوع برای کد اصلی برنامه
npm run typecheck:tests  # بررسی نوع برای فایل‌های تست
```

## Build نهایی

```bash
npm run build
```

خروجی در پوشهٔ `dist/` ساخته می‌شود — شامل فایل‌های استاتیک، `manifest.webmanifest`،
و Service Worker (`sw.js`). این پوشه همان چیزی است که روی GitHub Pages آپلود می‌شود.

### تنظیم مسیر (base path) برای GitHub Pages

اگر repo شما یک repo عادی (نه `username.github.io`) است، سایت شما زیر مسیر
`/نام-repo/` سرو می‌شود، پس باید هنگام build این مسیر را بدهید:

```bash
VITE_BASE_PATH=/نام-repo-شما/ npm run build
```

اگر repo از نوع `username.github.io` است یا دامنهٔ اختصاصی دارید، نیازی به این متغیر نیست
(مقدار پیش‌فرض `/` است).

## آپلود روی GitHub Pages

۱. یک repository در GitHub بسازید (یا از repo فعلی استفاده کنید).
۲. با مسیر درست build بگیرید:
   ```bash
   VITE_BASE_PATH=/نام-repo-شما/ npm run build
   ```
۳. محتوای پوشهٔ `dist/` را در یک branch به‌نام `gh-pages` قرار دهید. ساده‌ترین راه:
   ```bash
   npm install -D gh-pages
   npx gh-pages -d dist
   ```
۴. در GitHub، به تنظیمات repo بروید: **Settings → Pages** → Source را روی
   branch `gh-pages` (پوشهٔ `/root`) بگذارید.
۵. بعد از چند دقیقه، سایت روی آدرس
   `https://<username>.github.io/<نام-repo-شما>/` در دسترس است.
۶. برای نصب PWA روی موبایل/ویندوز، همین آدرس HTTPS را در مرورگر باز کنید و از منوی
   مرورگر «Install App» / «Add to Home Screen» را بزنید. باز کردن مستقیم فایل با
   `file://` برای تست نصب کافی نیست — حتماً از همین آدرس HTTPS استفاده کنید.

## مهاجرت از نسخهٔ قدیمی (فایل HTML قبلی)

از تب **«مهاجرت از پشتیبان قدیمی»** در برنامه، فایل پشتیبان JSON قدیمی را آپلود کنید:

1. برنامه یک گزارش Dry Run نشان می‌دهد (خطاها/هشدارها، جمع فروش و بهای خرید بازمحاسبه‌شده).
2. اگر خطای مسدودکننده نبود، دکمهٔ «تأیید و اجرای مهاجرت» را بزنید.
3. قبل از هر نوشتنی، یک پشتیبان کامل خودکار دانلود می‌شود — این فایل را نگه دارید.
4. سفارش‌ها و اقلام وارد می‌شوند. **پرداخت‌های تأمین‌کننده در پشتیبان قدیمی اصلاً
   ذخیره نشده بودند** (جزئیات در گزارش تحلیل) — آن‌ها را باید از تب
   «حساب تأمین‌کنندگان» به‌صورت دستی وارد کنید.

برای بازگشت به حالت قبل از مهاجرت، از تب «پشتیبان‌گیری و بازیابی» همان فایلی که در
مرحلهٔ ۳ دانلود شد را بازیابی کنید.

## چک‌لیست تست دستی

- [ ] فایل پشتیبان واقعی را در تب «مهاجرت» آپلود کنید و مطمئن شوید Dry Run بدون خطا
      (فقط هشدار) تمام می‌شود.
- [ ] بعد از تأیید مهاجرت، در تب «داشبورد» اعداد فروش/سود را ببینید.
- [ ] در تب «حساب تأمین‌کنندگان»، برای وحید نظری یک پرداخت هدفمند (targeted) به دو
      قلم مشخص ثبت کنید و مطمئن شوید فقط همان دو قلم تسویه می‌شوند و حساب علی ورساچ
      دست‌نخورده می‌ماند.
- [ ] همان پرداخت را حذف (soft delete) کنید و مطمئن شوید مانده اقلام به حالت قبل
      برمی‌گردد؛ سپس بازیابی کنید و مطمئن شوید دوباره تسویه می‌شوند.
- [ ] دکمهٔ «همگام‌سازی» را در همان صفحه دو بار پشت‌سرهم بزنید و مطمئن شوید هیچ عدد
      یا رکورد جدیدی ساخته نمی‌شود.
- [ ] در تب «اقلام سفارش‌ها» مطمئن شوید ستون پرداخت/مانده با تب «حساب تأمین‌کنندگان»
      یکسان است.
- [ ] در تب «گزارش روزانه» و «گزارش ماهانه» مطمئن شوید جمع‌ها با داشبورد یکی است.
- [ ] در تب «سود شخصی»، یک قانون سهم همکاری (مثلاً ۵۰٪ برای وحید) اضافه کنید و
      مطمئن شوید بدهی خرید تأمین‌کننده تغییر نمی‌کند.
- [ ] از تب «پشتیبان‌گیری و بازیابی» یک پشتیبان دانلود کنید، سپس همان فایل را
      بازیابی کنید و مطمئن شوید داده‌ها تغییری نکردند.
- [ ] برنامه را build و روی GitHub Pages آپلود کنید، در مرورگر موبایل باز کنید و
      نصب (Add to Home Screen) را امتحان کنید؛ حالت آفلاین (خاموش کردن اینترنت و
      باز کردن دوبارهٔ برنامه) را هم امتحان کنید.

## آنچه هنوز ساخته نشده

جزئیات کامل در `oms-pro-analysis-report.md`، خلاصه:

- صفحهٔ مشتریان، رابط کاربری تنظیمات قیمت‌گذاری (فرمول‌های علی/وحید فقط در موتور
  محاسباتی و تست‌ها پیاده شده‌اند، هنوز رابط کاربری ندارند)
- ویرایش یک پرداخت ثبت‌شده (فعلاً فقط ایجاد/حذف/بازیابی)
- نوع پرداخت جداگانه برای «پرداخت مستقیم مشتری به تأمین‌کننده»
